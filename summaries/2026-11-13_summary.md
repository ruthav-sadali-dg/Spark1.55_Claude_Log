## 20261113-001: Forced CB-A1/B1 trip bits in PLC not showing in Ignition

**Goal:** Forcing CB-A1 and CB-B1 "trip status" bits high in `MDC1_55_PLC.ACD` should make Ignition show the breakers as tripped, but Ignition still showed "Normal". Find out what Ignition reads and whether the right bits were being forced.

**Steps taken**
1. Found the PLC file at `C:\Users\SadaliR\Downloads\MDC1_55_PLC.ACD`.
2. Traced the Ignition tag for CB trip status:
   - Instance `tags/MDC-01/EPMS-01/.../SWBD-A1/CB-A1.json` uses UDT `EPMS/Systems/Trip Units/Equipment Modules/ABB/Tmax/v1_0_1`.
   - In that UDT, `Status/BKRTRIP` (states 0=Normal, 1=Tripped; "Breaker has Tripped" alarm) is an OPC tag at `ns=1;s=[{device}]1.IRUS40.12`.
   - `{device}` = `MDC-01-CB-A1` / `MDC-01-CB-B1`. In `config/devices/connections/construction/modbus-emax.json` these are **Modbus TCP connections straight to the ABB trip units** (10.12.1.70 and 10.12.1.71). In the local/sim profile they point at `e2e-sim` ports 511/512.
   - The one-line breaker components (`Breaker Square`, `Breaker PDC`) and the `Perspective/EPMS/Tmax` script read `BKRTRIP`.
3. Checked the PLC side (`EPMS/Systems/PLC/System Modules/PLC.json`, folder `Marshalling/CB_A1` and `CB_B1`). The PLC only carries hardwired XT7 signals from `MDC_01_Marsh_RIO:2:I` (5000_DI32), and there is **no trip tag**:
   - CB-A1: Control_Power_On Pt15, Alarm_Contact Pt16, Breaker_Closed Pt17, Breaker_Open Pt18
   - CB-B1: Control_Power_On Pt02, Alarm_Contact Pt03, Breaker_Closed Pt04, Breaker_Open Pt05
   - The `Alarm` tag is `!Alarm_Contact`. The XT7 alarm contact is normally closed, so a raw input of 1 means normal.
4. Looked inside the ACD read-only by decompressing its embedded gzip sections. It has the `MDC_01_Marsh_RIO:2:I` module and the comments "CB A1/B1 XT7 ALARM / BREAKER CLOSED / BREAKER OPEN / CONTROL POWER STATUS". No CB trip-status tag. Rung text is stored tokenized by object ID, so comments were not mapped to individual points.

**Root cause**
- The "Normal/Tripped" status in Ignition comes from the breaker trip unit over Modbus, not from the PLC. A force in the PLC can't change it.
- Separately, if the forced bit was the XT7 alarm input, forcing it **high** is the normal state because the contact is normally closed and inverted.

**How to simulate a trip (options)**
- To trip the Ignition CB status: write/override `Status/BKRTRIP` in Ignition (Designer tag override or a memory-tag test), or use the sim (`e2e-sim` port 511/512, IR 40 bit 12) in the local profile. A real trip-unit test is the other route.
- To test the PLC hardwired path: force `MDC_01_Marsh_RIO:2:I.Pt16.Data` (A1) / `Pt03.Data` (B1) to **0** to raise `Marshalling/CB_x1/Alarm`. Force `Pt18`/`Pt05` (Open) to 1 and `Pt17`/`Pt04` (Closed) to 0 to show the breaker open.
- Make sure I/O forces are **enabled** in Studio 5000. Installed but disabled forces have no effect.

**Outcome:** Diagnosis only. No project files changed.

## 20261113-002: Connecting to a VESDA unit with Xtralis VSC

**Goal:** Connect a laptop to the site VESDA detector with Xtralis VSC (VESDA System Configurator).

**Site details:** Ignition polls `MDC-01-Vesda` over Modbus TCP at `10.12.1.91` (`construction/modbus.json`), so the unit is a VESDA-E with Ethernet.

**Procedure (Ethernet)**
1. Install Xtralis VSC from the Xtralis/Honeywell site and run it as admin.
2. Put the laptop on the same subnet: plug into the MDC switch, or straight into the detector's Ethernet port. Set a free static IP, e.g. 10.12.1.x/24 (ask the network owner for a free address).
3. Check the link with `ping 10.12.1.91`.
4. In VSC: **Connect** → **Ethernet** (TCP/IP) → enter `10.12.1.91`, or use discovery. Log in with the site credentials.
5. VSC loads the detector config and shows live status: airflow, smoke level, faults.

**Alternative:** the USB port behind the detector's front cover. Use **Connect** → **USB** in VSC, and install the USB driver if Windows doesn't see the device.

**Troubleshooting:** a Windows firewall prompt, the wrong subnet, or a VSC version too old for the detector firmware. Ignition's Modbus polling runs alongside VSC and doesn't block it.

**Checking whether the VESDA already has an IP**
- In the Ignition Gateway, go to Config → OPC UA → Device Connections and look at `MDC-01-Vesda`. **Connected** means it has 10.12.1.91 and answers Modbus on port 502.
- `ping 10.12.1.91`, then `arp -a` to see the MAC address.
- Scan the subnet: `nmap -sn 10.12.1.0/24` or Advanced IP Scanner. Match the MAC address to the label on the detector.
- Run VSC's discovery scan on the same network segment.
- Check the DHCP server leases or the switch's MAC address table.

**Assigning a static IP**
1. Connect over USB with VSC. This doesn't need an IP.
2. Open the detector's network/Ethernet settings. Turn DHCP off and set IP 10.12.1.91, mask 255.255.255.0, and the gateway per the IP schedule.
3. Turn on Modbus TCP if it's a separate setting. Write the settings to the detector and power-cycle it or reconnect.
4. Confirm with ping, then check that the Ignition device shows Connected.
- If the detector is on DHCP with no DHCP server around, it may pick a 169.254.x.x address. Put the laptop on 169.254.x.x to reach it, or just use USB.

**Safety (VESDA):** VESDA is a fire life-safety device. Coordinate with the fire alarm contractor/AHJ before changing config or running tests that could send alarms to the FACP.

## 20261113-003: CLSS Gateway initial setup and IP assignment from a computer on Eth2

**Goal:** Use the Honeywell CLSS Gateway Installation & User's Manual (P/N LS10248-000HW-E Rev H) to set up a CLSS gateway board and set its IP, with the laptop plugged into the board's "Ethernet 2" port.

**Key facts from the manual**
- The port **labeled "Ethernet 2" (J3)** is logically **Eth0**, the configuration port. Its IP is fixed at **192.168.10.190** and it can't be changed. The web Configuration Tool runs only on this port.
- The port **labeled "Ethernet 1" (J4)** is **Eth1**, the permanent LAN port for Modbus, BACnet, Horizon and CLSS Cloud. This is the port you give a static IP. DHCP and NAT are not supported.
- Config mode: hold **S6** for at least 6 s. **DL3** goes solid. To exit, press S6 again until DL3 flashes.
- Web tool: `https://192.168.10.190:9443/config/index.html` in Chrome. The certificate is self-signed, so click Advanced → Proceed. The default password is in the manual ([REDACTED]); you must change it on first login.
- VESDA-E: the detector also connects to Ethernet port 2 (J3). The gateway automatically takes **the VESDA IP + 1**, so leave that address free. Minimum gateway firmware is 3.3.4.12.

**Procedure**
1. Power the board with 24 VDC on P2.
2. Plug the laptop into the port labeled **Ethernet 2 (J3)**. Set the laptop NIC to a static IP of 192.168.10.x/24 (not .190), e.g. 192.168.10.10 / 255.255.255.0, with no gateway.
3. Hold S6 for 6 s or more and wait for DL3 to go solid. Check with `ping 192.168.10.190`.
4. Open the web tool in Chrome, log in, and change the password.
5. **Gateway Settings:** set the panel brand, comm port and baud rate, and a unique Node Address (64-249, default 235). Click SAVE.
6. **Network Settings → ETHERNET 1 SETTINGS:** enter the static IP, subnet mask, default gateway and DNS for the site LAN. Click SAVE. Optionally set TIME SYNC and WLAN too.
7. For Modbus, open Modbus Settings. Authorized Client IP is optional and restricts which client may connect. Click SAVE.
8. Press S6 until DL3 flashes to leave config mode. Unplug the laptop, connect Eth1 (J4) to the LAN, and point the Modbus/BACnet client at the Eth1 IP.

**Gotchas**
- Configure one gateway at a time. They all ship with the same Eth0 IP and node number, so two at once will conflict.
- If the VESDA-E is on J3, the gateway sits at VESDA IP + 1 on that link. Plan the addresses before you connect it.
- Modbus or BACnet may need a one-time feature activation in the CLSS App: Fixed Gateways → site → ADD ACTIVATION.

**Outcome:** Procedure written from the manual. No device or project changes.
