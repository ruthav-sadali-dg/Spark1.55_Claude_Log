# Session Summaries – 2026-11-20

## 20261120-001: Laptop can't ping PLC / Flex IO on an unmanaged switch

**Goal:** Find out why a laptop can't ping a PLC (10.12.0.86) and two Flex IO Ethernet adapters (10.11.0.84, 10.11.0.89) connected to a TP-Link TL-SG605P unmanaged switch. The laptop has several static IPs on one NIC (Control Panel > adapter > IPv4 > Advanced).

**Steps and findings:**
1. **Check the laptop config.** `Get-NetIPAddress` showed the Ethernet NIC with 10.11.0.250/24, 10.12.0.250/16 and 192.168.10.250/24, link up at 100 Mbps. Three default gateways were set on the NIC. That's unnecessary on an isolated control network, so leave the gateway blank.
2. **Check routing.** `route print -4 10.*` showed both subnets on-link through Ethernet, so the laptop side was correct.
3. **Ping with a fixed source and check ARP.** `ping -S 10.11.0.250 10.11.0.84` and similar all timed out. `Get-NetNeighbor -InterfaceAlias Ethernet` showed **Incomplete** for every device, meaning none of them answered ARP. Firewalls don't block ARP, so the cause is the physical link, or the devices aren't actually at those IPs.
4. **Look for traffic on the wire.** The session wasn't elevated, so a pktmon capture wasn't possible. `Get-NetAdapterStatistics` showed about 10 broadcast frames per second arriving, so something on the switch is talking. Likely BOOTP requests from unconfigured modules, or ARP from the PLC.

**Likely causes (check in this order):**
- The Flex IO adapters aren't at the expected IPs. Rockwell adapters ship in BOOTP/DHCP mode, or the rotary/thumbwheel switches force 192.168.1.xxx. Run Rockwell's BOOTP-DHCP tool or Wireshark to see the MACs requesting addresses, then assign the IP and disable BOOTP.
- The PLC's IP may only be configured in the project and never downloaded, or the controller's Ethernet port is on a different interface or module.
- Check the link LEDs on each switch port. The laptop linking at 100 Mbps on a gigabit switch suggests a cable or port issue worth checking.
- Design note: the PLC is on 10.12.x and the IO on 10.11.x. A controller can't own IO on a different subnet without a router, so the IO should probably go on the PLC's subnet.

**Tools to use:** Wireshark (filter `arp || bootp`), the Rockwell BOOTP-DHCP Commissioning Tool, and RSLinx/FactoryTalk Linx Ethernet/IP browse.

**Outcome:** The laptop was ruled out as the cause and the problem narrowed to device addressing or the physical link. The user was given next steps.
