
## 20261116-002: Honeywell CLSS Gateway not pingable after IP change

**Goal:** Work out why a CLSS Gateway can't be pinged after its IP was changed (Modbus licensing suspected).

**Steps:** Extracted text from the CLSS Gateway Installation and Users' Manual (P/N LS10248-000HW-E Rev H) with a throwaway pypdf venv, because no PDF tools were installed. Searched it for IP, port, ping and licensing guidance.

**Key findings (SOP draft):**
- Ping has nothing to do with Modbus licensing. "Modbus Support" is a one-time feature activation done in the CLSS App (Fixed Gateways > OC > Add Activation). It only affects Modbus data on TCP 502.
- The gateway has two Ethernet ports with different roles:
  - **Eth0 (J3):** configuration only, fixed IP 192.168.10.190. Web tool at https://192.168.10.190:9443/config/index.html, reachable only in config mode (hold S6 for 6 s; DL3 goes solid).
  - **Eth1 (J4):** the only port for Modbus clients. This is the port the configured static IP applies to.
- The usual mistake: you set the IP on Eth1 but ping from a cable on Eth0, or the other way round.
- Other checks: Eth1 subnet mask and gateway; your PC on the same subnet (NAT and proxies are not supported); IP conflicts when several gateways ship with the same default IP; cabling and power; LEDs; leaving config mode / rebooting after a change; Authorized Client IP (should be 0.0.0.0 unless intended; it filters Modbus, not ping); Wireshark and Modscan for debugging.

**Outcome:** Gave the user a troubleshooting list based on the manual. No changes were made to any system.

## 20261116-001: Switch crusoe.mdc.scada to latest dev and restart the compose stack

**Goal:** Compose down, check out and pull the latest `dev`, compose up.

**Steps:**
1. `docker compose down`: removed all 6 `sny-edge-*` containers and the network.
2. `git checkout dev`: **partly failed**. "unable to unlink ... Permission denied" on many files. `git pull` then refused ("local changes would be overwritten").
3. Root cause: `IGNITION_UID/GID` are commented out in `.env`, so the Ignition gateways run as uid 2003 and chown the bind-mounted checkout. About 61k files were not owned by the user.
4. Fixing ownership with a root docker container was blocked by Claude Code's permission check twice. The user ran `sudo chown -R sadalir:sadalir ~/crusoe.mdc.scada`.
5. Cleanup: `git stash push` (kept the half-checkout diffs as a backup). Deleted only the untracked files that are tracked in the old feature branch (33 files) and the empty dirs left behind. Kept the pre-existing untracked `gateway-network-incoming` dir.
6. `git pull --ff-only`: fast-forward 4c495609..279c4355.
7. `docker compose up -d`: broker, postgres-db, backend and IO-01 healthy; frontend starting; liquibase exited 0 (normal).

**Troubleshooting note (SOP):** If a branch switch fails with "Permission denied" in this repo, the gateways own the checkout. Run `docker compose down`, then `sudo chown -R $USER:$USER <repo>`, then reset or clean and switch again. Permanent fix: set `IGNITION_UID=1000` / `IGNITION_GID=1000` in `.env` (see the comment at docker-compose.yml:128).

**Outcome:** Repo on `dev` at 279c4355, level with origin, and the stack is running. `.env` was not changed (pending the user's decision).
